# 寄养前检查与今日任务

## 预约和入住规则

- 新预约、空档查询和草稿确认均拒绝早于当天的入住日期，单次 1 至 60 晚。
- 档期使用半开区间 `[start_date, end_date)`。同一宠物不能在不同笼舍重复预约重叠日期；相邻档期允许。
- 确认草稿时重新核对宠物档案，并按宠物、笼舍顺序加行锁。在 MySQL 下使用锁定读复核冲突，避免事务快照漏掉刚提交的预约。
- 入住要求：订单已确认、全额付款、`start_date <= 今天 < end_date`、宠物档案有效、笼舍未维护或清洁、无其他在住宠物。
- 已入住订单重复调用仍幂等返回，不重复发送通知。

## 健康资料核对

`GET /api/boarding/health-check?pet_id=&start_date=&end_date=`。

复用宠物档案权限：宠物主仅能核对自己的宠物，寄养员和管理员可核对工作范围内的档案。服务不修改健康记录，也不自动下单。

- 疫苗与驱虫按同名项目取最新有效记录，排除已删除与未来日期记录；不会用一项新疫苗覆盖其他疫苗项目。
- 缺记录、缺下次到期日、入住前或当天到期、寄养期间到期列为待核对。退房日不在寄养区间内。
- 已录入过敏信息列为交接事项；未填写显示“需确认”，不推断为无过敏。
- 近 7 天症状记录列为待核对，不推断是否已恢复。
- 返回来源记录 ID、记录日期、下次到期日、核对日期及业务规则说明。不代表医学诊断或入住许可，不作为强制拒单规则。

草稿响应新增 `health_check`，预约页和智能助手草稿卡片共用展示组件。新增站内只读工具 `get_boarding_health_check`，按宠物名称查询并复用服务层权限。MCP 对外工具白名单仍为原有 7 项。

## 寄养员今日任务

`GET /api/boarding/tasks/today`，仅寄养员和管理员可访问。

| 分组 | 规则 |
| --- | --- |
| 待接单 | 未结束预约期间的 pending 订单 |
| 待入住 | 预约期间内的 confirmed 订单，未付款仍展示并提示付款 |
| 待退房 | 在住且退房日为今天或已过期 |
| 未填日报 | 今天在预约日期范围内、在住且无当日日报 |
| 异常日报 | 在住宠物当日日报出现食欲差、偏软 / 腹泻或精神低落 |

任务使用批量订单和日报查询，不改变业务状态。首页按角色展示：宠物主保留档案与提醒，寄养员和管理员显示今日任务，管理员另有运营管理入口。任务支持定位对应订单、打开日报。

## 验证与边界

新增自动化测试覆盖健康检查来源 / 日期边界 / 缺失资料、身份隔离、助手工具序列化、宠物重叠档期、跨日草稿、失效宠物、付款 / 入住时间限制、清洁状态以及任务随入住 / 日报 / 退房的变化。

pytest 使用临时 SQLite；MySQL 并发事务仍需在专门的集成环境验证。健康检查按录入日期与同名项目核对，不能验证证明真伪或保证项目覆盖所有接种要求。本次不增加数据库字段或迁移，也不修改现有订单数据。
