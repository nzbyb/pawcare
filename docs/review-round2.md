# 页面评审后的第二轮修改

## 占用和照护规则

- `checked_in` / `boarding` 订单到预约结束日仍未退房时，继续阻止该宠物和笼舍的新预约，直到实际办理退房。未来档期也暂时保留，避免在离店时间不明确时超售。
- 空档查询、草稿创建及确认均检查逾期占用。清洁和维护中的笼舍不能接受新预约。
- 后台优先展示实际在住订单，标记“实际在住 / 逾期在住 / 预约预留”。日期选择表示当时已知的预约及当前在住状态预测，并非完整历史入住快照。
- 逾期在住仍计入未填日报。日报允许补录实际入住至今天的日期，完成订单截至实际退房日，禁止提前填写未来日报。

## 全款与退款

- 新预约采用全款支付，不收独立定金。历史 `deposit` 字段保留，不重写旧订单。
- 界面统一显示总额、已付、待付、已退；交接单同步使用全款说明。
- 取消未入住的已付订单，在同一事务内生成全额退款申请。历史已取消订单可手动申请。
- 管理员在寄养订单页审核执行退款；宠物主可看进度，寄养员无退款权限。
- 退款状态：`requested` 待审核 → `processing` → `succeeded`；异常为 `failed`，使用原退款号重试。只有渠道成功才更新为已退款。
- 模拟支付使用模拟退款。支付宝原路退款使用签名请求和验签响应，核对商户交易号及退款金额，固定退款号确保重试幂等。不要把模拟测试当作真实网关联调已完成。
- 取消后延迟到账仍记录成功收款，并生成待审核退款；不恢复已取消订单。
- 原 `paid_amount` 保留收款历史，退款金额单独记录。近7/30天统计按实际支付及退款完成日计算净收款。

新增迁移 `d5f9a2c7b4e1` 只增加 `refund_orders` 表，不改写既有业务数据。启动前在 backend 执行 `python -m alembic upgrade head`。

## 页面体验

- 普通路由切换回顶部，历史返回恢复滚动位置；任务链接仍定位对应订单。
- 预约页拆成新建预约和我的订单；日期占满一行，健康检查明细可展开。
- 员工首页默认选择有任务的分类，按异常、退房、缺日报、入住、待接单排序。异常为0时不用警告色。
- 健康记录支持编辑，修改时同步提醒标题和到期日；提醒类型使用中文，“即将到期”栏目改“待处理提醒”。
- 助手聊天高度适配视口，输入框保持在聊天区底部；历史及说明可收起，历史消息展示时间及过期信息提示，可填入重新查询问题。示例采用相对日期，不需要再改固定月份。
- 后台新增最近7/30天订单趋势、实收、退款、净收款和今日实际入住率，并提供每日明细。

## 演示数据

`python scripts/review_business_data.py` 仅输出订单ID及问题类别，用于检查未付款在住、逾期、已取消待退和重叠预约。旧数据不自动删除、不自动退房或退款。演示前应挑选一致的场景或在单独演示库重建数据。
